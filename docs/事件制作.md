# 事件节点制作

在 Godot 文件系统中复制 `assets/events/blacksmith.tres`，然后在检查器中修改事件资源。将新资源拖入 `assets/events/catalog.tres` 的 **Events** 数组即可参与抽取。

- `event_id`：唯一标识；`title`、`npc_name`、`story`：事件标题、人物名称、剧情。
- `background_id`：背景库编号 1—11；设为 0 时使用自定义 `background`。`portrait` 为可选 NPC 立绘，留空即可创建无 NPC 事件。
- `min_floor`、`max_floor`：允许出现的层数，包含边界。铁匠为 1—2 层、旅人为 3—5 层、破败教堂为 1—5 层。
- `choices`：配置 2—3 个选项。复制资源时，将需修改的内嵌资源设为“唯一”，避免多个事件共用同一个选项。

每个选项可配置显示文字、金币消耗、攻击增加、遗物 ID、恢复生命、生命消耗、金币奖励和结果文本。显示文字也应同步写明收益与代价。金币或生命不足时按钮禁用；唯一遗物已经持有时也禁用对应选项。一次事件只能完成一个选项。

`battle_map` 留空表示结束事件；拖入可编辑战斗地图场景则表示进入普通战斗，胜利后结算并返回路线。地图沿用现有 `EditableBattleMap` 格式，敌人出生标记需包含普通战斗的配置。铁匠的三个选项均不触发战斗。

事件按种子与节点固定抽取，只从符合当前层数限制的资源中选择；读取预览或打开界面不会消耗整局随机数。新增规则时应确保每层至少有一个可用事件。

武器打磨提供本局永久攻击 +3，升级和下一场战斗保留，新开局清空。精良软甲仅从事件获得：每次战斗内形态转换完成后增加 5 护盾，可与日蚀护镜同时生效，战斗结束清空。

实际界面入口为 `scenes/events/story_event.tscn`，布局脚本为 `scripts/events/story_event.gd`，采用 1152×648 设计尺寸等比适配窗口。剧情框与按钮使用本次提供的素材；按钮不同状态从同一素材表中取区域。

路线、事件、商店、秘藏及休整界面共用 `scripts/ui/expedition_header.gd` 信息栏：层数、生命、攻击、金币、等级与当前等级经验进度。图标及数字使用 `assets/ui/stats/` 素材，`regions.json` 记录原图中的有效区域，不修改原图。种子显示在 ESC 设置的窗口大小选项下方。

事件对话框保持素材比例，宽度为原版本的 80%，可见底边距屏幕下方约 25 个设计像素；NPC 相对上一版本向右 120、向上 40 个设计像素。NPC 上方不再重复显示标题与角色数值。


背景库为 `assets/backgrounds/library.tres`：background_1 村庄、background_2 遗迹、background_3 酒馆、background_4 密林、background_5 山谷、background_6 湖畔、background_7 雪原、background_8 洞穴、background_9 教堂、background_10 储藏室、background_11 街道。旧的城镇背景已移除。

背包新开局有 6 槽，同类遗物每叠加一件也占一槽。商店、奖励、事件、战斗掉落统一检查容量；满包不能领取新遗物，奖励节点可以选择放弃领取。休憩之所可在“休息”与“整理背包”之间选择一次，整理后本局永久增加 1 槽。

事件选项的 `exchange_relic` 设为 true 可进入遗物选择与确认流程。取消不会修改背包，确认后移除所选遗物的一件并给予一个随机常规遗物（排除刚丢弃的种类，以及已持有的唯一遗物）；满背包也可一换一。替换后生命上限、攻击等派生属性会立即更新。
